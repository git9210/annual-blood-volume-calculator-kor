# 헌혈 계산기 4.2.0

헌혈 기록과 직전 1년의 계산량을 기기 안에서 관리하는 Android 앱입니다.
개인이 제작한 비공식 도구이며, 실제 헌혈 가능 여부는 기관의 문진·검사로 결정됩니다.

## 배포 상태

- v4.2.0은 헌혈 기록에도 화면 편집을 추가한 기능 버전입니다. 파일만 제작하며 GitHub 게시는 별도 요청이 있을 때 진행합니다.
- v4.0.3은 앞선 별도 요청에 따라 GitHub에 게시했습니다.
- [기존 v4.0.1 Release](https://github.com/git9210/annual-blood-volume-calculator-kor/releases/tag/v4.0.1): 사용자가 Play 프로텍트 차단을 보고했습니다. 원인·해제 여부는 확인되지 않았습니다.
- [전체 버전별 변경점·APK 실측 용량·현재 기능](VERSION-HISTORY.md)
- 개인 서명키와 비밀번호는 공개하지 않습니다. 아래 버전별 설명은 제작 당시의 변경 이력이며, 현재 동작은 v4.2.0 설명을 우선합니다.

## 설치

배포용 파일은 `Annual-Blood-Volume-Calculator-4.2.0-Small.apk`입니다.
기존 사용자는 앱을 삭제하지 말고 새 APK를 열어 **업데이트 설치**하세요.
패키지 `kr.bloodnote.app`, 기존 서명, 저장 키, 암호화 방식과 데이터 형식을 유지합니다.
새로 설치한 앱은 기록과 계획이 모두 0건입니다.

- Android 8(API 26) 이상. 증명서 PDF 읽기는 Android 15(API 35) 이상.
- versionName `4.2.0`, versionCode `52`.
- 이번부터 작은 월간 달력만 제공합니다. 기존 Large 설치에도 같은 서명의 이 APK로 업데이트할 수 있습니다.

## 4.2.0 추가: 헌혈 기록 화면 편집

- 헌혈 기록 화면에서도 설정 옆 **화면 편집** 아이콘을 표시합니다. 확인 후 기존과 같은 편집 모드에서 길게 누르거나 ↑/↓로 이동하고, −로 숨기거나 하단의 반투명 미리보기에서 ＋로 다시 표시할 수 있습니다. 상단 **저장**을 누르면 재실행 후에도 유지됩니다.
- 편집 가능한 다섯 항목은 **최근 1년 기록 입력 확인 → 기록 추가·증명서 → 헌혈 종류별 횟수 → 헌혈 기록 목록 → 봉사시간**입니다. 휴대폰·넓은 화면 모두 항목은 한 줄 전체 폭을 사용합니다. 다섯 영역을 각각 카드/안내 영역으로 구분하고 기존 색상·글꼴·버튼과 목록 기능을 사용합니다.
- **취소** 또는 Android 뒤로가기로 초안을 버릴 수 있습니다. **기본 배치로 초기화**는 두 번째 확인을 거쳐 현재 화면의 순서·표시만 되돌립니다. 다른 화면 배치와 헌혈 기록·계획·접기 상태는 유지합니다.
- 배치와 숨긴 항목은 기존 암호화 저장소·암호화 백업에 포함합니다. 헌혈 기록 화면 설정이 없는 이전 데이터는 다섯 항목을 기본 순서로 표시합니다. 이전 백업에 해당 화면 설정이 없으면 현재 설정을 보존하며, 백업에 명시된 화면 설정은 복원합니다.
- 숨긴 항목은 일반 화면에서 표시/렌더링하지 않습니다. 편집 미리보기에서는 입력·삭제·PDF/VMS 링크 등 기능을 실행하지 않도록 기존 inert/터치 차단을 적용합니다. 저장 실패 시 기존 설정을 보존하고 초안을 다시 저장할 수 있습니다.
- JavaScript **231개**와 Android 셸 동작 검사, APK 웹 파일/참조 17개씩, 기존 서명·ZIP·정렬 검증을 통과했습니다. Java 소스·DEX·Android 리소스와 네트워크/계산/PDF/암호화 처리는 v4.1.0과 동일합니다. 실제 기기 화면·터치·설치·Play 프로텍트 검사는 미실시입니다. 상세 결과는 `REVIEW-4.2.0.md`를 참고하세요.

## 4.1.0 추가: 봉사시간과 VMS 헌혈실적 연계

- 헌혈 기록 화면의 목록/페이지 이동 아래에 **봉사시간** 카드를 표시합니다. **총 인정 봉사시간**과 **현재 연도 봉사시간**을 나란히 보여주며, 등록된 완료 기록 1회에 종류와 관계없이 4시간으로 계산합니다.
- VMS 공식 안내의 인정 시작일인 **2010년 7월 1일** 이후 기록을 대상으로 합니다. 올해는 직전 1년이 아닌 한국 시간의 해당 달력 연도이며, 계획·미래 일정·제한 기간은 합산하지 않습니다. 0건일 때도 0시간을 표시합니다.
- 종류 필터나 현재 페이지에 표시된 기록 수와 관계없이 전체 완료 기록으로 계산합니다. 기록 추가·수정·삭제·되돌리기·PDF/텍스트 등록·백업 복원 시 자동 갱신되며, 연도가 바뀌어도 현 연도로 갱신합니다.
- 작은 글씨의 **헌혈실적연계하러가기**는 <https://www.vms.or.kr/auth/blood.do>로 연결합니다. 누르기 전에는 접속하지 않습니다. 매번 데이터 요금·외부 사이트 이용·앱 기록 미전달 안내와 VMS에서 직접 로그인/연계해야 한다는 안내를 확인한 뒤 기본 브라우저로 엽니다. 취소하면 열지 않습니다.
- 표시는 이 앱에 등록된 기록의 계산값입니다. VMS의 공식 인정 완료 내역을 조회하거나 자동으로 연계하는 기능은 아닙니다. 링크에 기록·종류·횟수·PDF·암호를 붙이지 않습니다.
- JavaScript 225개 검사와 변경한 외부 연결 Java 코드의 105개 호스트 검사, Android 셸 동작 검사와 APK 서명/구조 검증을 통과했습니다. 새 권한·계정 수집·서버·라이브러리는 없습니다. 자세한 결과는 `REVIEW-4.1.0.md`를 참고하세요.

## 4.0.5 수정: 일정 시뮬레이터 접기 상태 유지

- 나의 장기 계획과 헌혈 제한 기간도 각 항목의 접기·펼치기 상태를 기기에 자동 저장하고 앱 재실행 시 복원합니다. 목록이 0건이어도 기억합니다. 한눈에 보기의 네 항목과 각각 독립적으로 저장합니다.
- 업데이트 설치 후 원하는 상태로 한 번 접거나 펼쳐 주세요. 설정이 없는 이전 데이터는 기존처럼 두 목록을 접어서 표시합니다. 이미 저장한 한눈에 보기 상태와 기록·계획·제한 사유를 유지합니다.
- 같은 암호화 저장소와 비밀번호 백업에 `plannerSections` 선택 필드만 추가합니다. v4.0.4 등 이전 백업에는 이 필드가 없어도 현재 접기 상태를 보존합니다. 새 설정 메뉴나 별도 저장 버튼은 없습니다.
- 정렬·화면 이동·달력 이동·배치 편집 후에도 유지합니다. 편집 미리보기·예시 데이터·분리된 이전 화면의 이벤트는 실제 설정을 덮어쓰지 않습니다. 중복 이벤트는 저장하지 않으며, 실패하면 저장 전 상태로 되돌리고 안내합니다.
- JavaScript 219개 검사와 Android 셸 동작 검사, APK 웹 파일 17개·참조 17개 연결 검사, 기존 서명과 APK 구조 검증을 통과했습니다. Java 소스·DEX·리소스는 v4.0.4와 동일합니다. 실제 기기 강제 종료·재부팅 및 Play 프로텍트 검사는 미실시입니다.
- 자세한 결과와 APK SHA-256은 `REVIEW-4.0.5.md`에 있습니다.

## 4.0.4 수정: 한눈에 보기 접기 상태 유지

- 다음 헌혈 예상일·다가오는 계획·계산에서 빠지는 기록·최근 헌혈 기록의 접기/펼치기를 기기 안에 자동 저장합니다. 앱 종료·재실행 후에도 항목마다 마지막 상태를 복원합니다.
- 업데이트 후 원하는 상태로 한 번 접거나 펼쳐 주세요. 기존 버전의 미저장 화면 상태를 추측해 복원하지 않습니다. 설정이 없는 항목의 기본값은 기존처럼 펼침입니다.
- 기존 암호화 저장소와 백업에 표시 상태만 추가합니다. 예시 체험과 화면 편집 미리보기는 실제 설정을 덮어쓰지 않습니다. 저장 실패 시 기존 설정과 표시를 유지하고 안내합니다.
- 내용이 같은 렌더링 이벤트는 다시 저장하지 않습니다. 상태 변경 시 전체 화면을 다시 그리거나 헌혈 계산을 반복하지 않습니다.
- JavaScript 213개 검사, Android 셸 동작 검사, APK의 웹 파일 17개와 참조 17개 검사, 기존 서명 및 APK 구조 검증을 통과했습니다. Java 실행 코드·DEX·리소스와 개인정보 처리·통신·계산 규칙은 v4.0.3과 같습니다. 실기기 종료/재부팅과 Play 프로텍트 판정은 미검증입니다.
- 상세 결과와 APK SHA-256은 `REVIEW-4.0.4.md`에 있습니다.

## 4.0.3 보완: 직접 설치 기능과 권한 제거

- v4.0.2에서도 차단이 이어졌다는 사용자 보고에 따라 업데이트 기능을 최소 권한 방식으로 바꿨습니다. `REQUEST_INSTALL_PACKAGES`, APK 다운로드/파일 검사/설치 요청, 설치 허용 설정 이동, APK 제공 ContentProvider를 제거했습니다. 현재 선언 권한은 `INTERNET` 하나입니다.
- **설정 → 업데이트 확인 → 이번 연결 동의 → 새 버전·APK 크기 안내 → 배포 페이지 열기 → 기본 브라우저에서 직접 다운로드 → Android 설치** 순서입니다. 앱이 자동 설치하거나 브라우저를 자동으로 여는 방식은 아닙니다. 브라우저 열기에도 별도 동의가 필요합니다.
- 앱은 지정 저장소의 최신 정식 Release 메타데이터만 조회합니다. 512KiB로 제한하고 주소 리디렉션을 따라가지 않습니다. 정식 태그·Small APK 이름/주소/크기를 확인한 뒤 그 태그의 배포 페이지를 안내합니다. 내려받은 APK 자체의 해시·서명·패키지 검사는 더 이상 앱에서 하지 않습니다. Android의 설치 검증은 그대로 적용됩니다.
- 이전 버전이 남긴 앱 내부 `app-update/update.apk` 및 UUID 이름의 `.part` 파일만 정리합니다. 새 버전은 APK를 내부에 저장하지 않습니다. 브라우저 다운로드 파일은 다운로드 폴더 등에 남을 수 있으며 사용자가 직접 삭제해야 합니다.
- 기록/계획/설정/계산/암호화/PDF 모듈과 패키지·기존 서명을 유지합니다. 새 외부 라이브러리·아이콘·통신 대상은 추가하지 않았습니다.
- **747개 자동 검사**(JavaScript 209개, Java 및 Android/HTTPS 대역 538개), APK 내 웹 파일/서명/정렬 검사 통과. 기기 설치 및 Play 프로텍트 차단 해제는 확인하지 못했습니다.
- 이 권한은 경고가 없었다고 보고된 v4.0.0에도 있었습니다. 따라서 **권한이 원인이라고 확정하거나 차단 해제를 보장하지 않습니다.** 상세 비교와 검증 한계는 `REVIEW-4.0.3.md`를 참고하세요. v4.0.3은 이후 별도 요청으로 GitHub에 등록했습니다.

## 4.0.2 비교 검수 및 업데이트 임시 파일 정리

- v4.0.0·v4.0.1 배포 APK를 직접 비교했습니다. Android 실행 코드·권한·아이콘·계산/암호화 모듈은 동일합니다. 실제 동작 변경은 날짜 범위 검사, 동일 백업 재선택, PDF 되돌리기의 마지막 화면 처리 세 곳입니다. 이 변경이 Play 프로텍트 차단의 원인이라는 근거는 확인하지 못했습니다.
- 설치 성공으로 앱 프로세스가 교체되어 결과 콜백을 받지 못해도, 다음 시작 시 내부 캐시의 APK가 이미 설치한 동일/이전 버전이면 정리합니다. 설치 중일 수 있는 더 새 버전 APK는 시작 시 삭제하지 않습니다.
- 설치 허용 안내에서 앱을 벗어나면 쓰지 않는 준비 파일을 정리합니다. Android 설치 설정/설치 프로그램으로 정상 전달한 파일은 결과가 돌아올 때까지 보존합니다. 정리할 때 APK URI의 임시 읽기 권한도 회수합니다.
- v4.0.1의 오류 수정 3건은 유지합니다. 기록·계획·설정·암호화 저장·백업 형식, 패키지와 기존 서명을 유지하며 새 권한·외부 라이브러리·통신을 추가하지 않았습니다.
- JavaScript 209개 + 기존 Java/Android 호스트 검사 367개 + 새 업데이트 수명 주기 검사 77개, 합계 653개 통과. 실제 Android 설치 및 Google의 차단 해제는 검증하지 못했습니다.
- 이 버전을 ‘Play 프로텍트 차단 해결 확인판’으로 표시하지 않습니다. 자세한 비교·수정·검증 범위는 `REVIEW-4.0.2.md`에 있습니다.

## 4.0.1 재검수: 날짜 입력·백업 재선택·마지막 화면 수정

- 달력의 **다른 날짜로 바로 이동**에서 지원 범위(1900-01-01~2199-12-31)를 벗어나거나 잘못된 날짜를 입력하면 안내 후 이전 날짜를 유지합니다. 날짜 입력 때문에 달력 표시와 이후 화면 이동이 실패하지 않도록 고쳤습니다.

## 화면 표시와 첫 화면

- 실제 헌혈 기록이 있는 달력 날짜는 파란 배경과 ✓로 표시하고, 해당 종류의 `완료`를 진하게 표시합니다. 날짜가 지났다는 이유만으로 계획을 완료로 표시하지 않습니다. 주말·공휴일의 붉은 날짜와 공휴일명은 유지합니다.
- 잔여량 카드의 배경색과 구간 설명이 함께 바뀝니다. 기본값은 아래와 같으며, 계산 기준에서 종류별 계산량을 바꾸면 구간과 충족 종류도 그 값에 맞춰 바뀝니다.

| 잔여 계산량 | 표시 |
| --- | --- |
| 44mL 이하 | 붉은색 · 최소 계산량 미만 |
| 45~89mL | 갈색 계열 · 혈장 계산량 충족 |
| 90~429mL | 파란색 · 혈장·혈소판·혈소판 혈장 계산량 충족 |
| 430mL 이상 | 초록색 · 네 종류 계산량 충족 |

이 표시는 계산량만 비교합니다. 간격·횟수를 포함한 조건은 다음 헌혈 예상일과 날짜 팝업에서 확인합니다. 입력 기록이 없으면 중립색과 `—`를 표시합니다.

설정 상단의 **첫 화면 설정**에서 한눈에 보기, 일정 시뮬레이터, 헌혈 기록, 마지막 화면 중 선택할 수 있습니다. 선택 즉시 기존 암호화 저장소에 저장되며 백업에도 포함됩니다. 앱을 완전히 종료한 뒤 다시 열면 선택한 화면으로 시작합니다. 실행 중 화면 복원은 보던 화면을 유지합니다. 기존 앱 및 첫 화면 설정이 없는 이전 백업은 한눈에 보기로 시작합니다.

뒤로가기는 팝업을 먼저 닫습니다. 고정 첫 화면을 고른 경우에는 다른 화면에서 그 첫 화면으로 돌아간 뒤 두 번 뒤로가기로 종료합니다. 마지막 화면을 고른 경우에는 현재 본 화면에서 바로 두 번 뒤로가기로 종료합니다. 로고를 누르면 계속 한눈에 보기로 이동합니다.

## 소스와 빌드

앱 실행에 별도 JavaScript 라이브러리, CSS 프레임워크, Gradle 플러그인은 사용하지 않습니다.

- `assets/`: HTML/CSS/JavaScript, 계산 엔진, 로컬 공휴일 자료·라이선스
- `src/kr/bloodnote/app/`: Android WebView, 보안 저장, PDF 읽기·분석, 수동 버전 확인·브라우저 연결·레드커넥트 실행
- `res/`: Android 리소스, 고정 빨강 PNG 아이콘, 아이콘 배치용 XML
- `tools/generate_icons.py`: 설정·새로고침 벡터만 재생성. 테마 PNG 로고는 유지
- `tests/`: 합성 데이터로 동작을 검사하는 개발용 코드

빌드 환경: JDK 17 이상, Python 3, Android SDK platform 36 및 build-tools 36.0.0.
SDK 위치를 `ANDROID_HOME`으로 설정하고 프로젝트 폴더에서 실행합니다.

```sh
python3 tools/generate_icons.py
node --test tests/*.test.mjs
node tests/android-shell-smoke.mjs
python3 tests/run-java-tests.py
python3 tests/run-red-connect-tests.py
python3 tests/run-certificate-password-tests.py
python3 tests/run-update-lifecycle-tests.py
python3 build.py
```

`build.py`는 표준 SDK 설치 경로와 기존 작업 환경의 SDK 경로를 지원합니다.
별도의 Python/Node 패키지 설치 없이 기본 빌드·JS 검사가 가능합니다.
선택 사항인 실제 PDF 비교 검사만 PC에 `pypdfium2`와 `pdftotext`가 필요합니다. 해당 도구는 APK/ZIP에 포함하지 않습니다.

PRIVATE 원본은 기존 `signing/release.jks`와 `signing/password.txt`로 빌드합니다.
GitHub 소스만 빌드하면 **새 서명키가 로컬에 생성**됩니다. 새 키로 만든 APK는 기존 배포 APK 위에 업데이트 설치할 수 없습니다. 기존 사용자에게 업데이트를 배포할 제작자는 원래 키를 공개 저장소 밖에서 보관하고 사용해야 합니다.

## 검증 범위

현재 v4.2.0 검증 결과는 `REVIEW-4.2.0.md`를 기준으로 확인하세요. 아래 내용은 이전 버전부터 누적한 검사 범위입니다.

176개 JavaScript 검사 및 앱 흐름 모의 검사: 기존 두 표시와 레드커넥트 버튼 두 위치의 독립적인 켜기·끄기, 재실행·암호화 백업·실패 시 복원·기록과 계산 보존, 첫 화면의 저장·재실행·복원·저장 실패, 잔여량 경계값과 사용자 지정 기준, 완료 날짜와 계획 구분, 날짜 팝업, 변경·취소·되돌리기, 중복 저장 방지, 저장 실패 복구, 자정 변경, 완료 기록 전환, 기존 백업·암호화·PDF 검토·오프라인 공휴일 표시를 확인했습니다.
마지막 화면의 재실행·설정 화면 복원·백업·저장 실패·되돌리기·예시 체험 격리와 팝업 바깥 터치·안쪽 여백·끌기·취소·PDF 작업 정리 동작을 모의 검사했습니다. 업데이트 버튼의 수동 호출·예시 모드 차단·기록 보존도 검사했습니다. 현재 Java 검사에는 버전·메타데이터 경계/임시 파일 정책 58개와 업데이트 동의·HTTPS·브라우저 연결 대역 168개, PDF 파서 19개, 공휴일 동의 8개, 암호화 11개가 포함됩니다. 제거된 APK 다운로드/파일 검증/설치 콜백 검사는 현재 통과 수에 포함하지 않습니다. 이전 업데이트 기능 제작 시 GitHub Release API와 공개 APK의 크기·검증값을 확인했습니다.
기존 검사에는 두 레드커넥트 스위치의 네 가지 조합, 자동 실행·통신 없음, 숨긴 위치의 실행 차단, 기존 데이터 보존, 재실행·암호화 백업·복원·저장 실패·예시 체험을 모의 검사했습니다.
레드커넥트의 날짜 팝업·최근 예정일 표시, 데이터 전송 없는 명시적 호출, 날짜 경과·삭제·완료 기록·예시 모드·오류 처리를 모의 검사했습니다. 실제 실행 클래스에 Android 대역 객체를 붙인 24개 검사로 동의·취소·중복 요청·백그라운드 전환·앱 제거·실행 오류·실행 대상과 전달값을 확인했습니다. 이는 실제 기기의 앱 전환 검사가 아닙니다.
이번 검사에는 제한 기간 경계·겹침·연간 만료일 불변·기존 간격·계획 충돌·저장 실패·편집·삭제·되돌리기·암호화 백업을 포함합니다. 실제 CertificateImporter/CertificateService에 Android 대역 객체를 붙여 평문/암호 문서 분기, 틀린 암호 재시도, 입력창 비우기, 취소·백그라운드·시간 제한·늦은 응답 무시·파일 핸들 정리를 확인합니다. 실제 Android의 PDF 복호화 엔진을 실행한 검사는 아닙니다.
자모 입력·글자 수 제한과 제한 기간 저장, 배치 초기화의 두 단계 동의·취소·뒤로가기·화면별 범위·재실행·암호화 백업·저장 실패 보존을 추가 검사합니다. v2.7.0에서는 항목 숨기기·다시 표시·전체 숨김·표시 항목 간 이동·저장 실패 재시도·현재 화면 초기화·이전 백업 호환·숨긴 화면의 불필요한 계산 생략을 검사합니다. APK 빌드, 서명 및 정렬 검사와 이전 서명 일치를 확인합니다. v2.5.2부터 빌드 시 `tools/verify_web_assets.py`가 컴파일된 Android 허용 목록·MIME과 실제 APK의 화면 파일·정적 참조를 검사합니다. v2.5.0·v2.5.1 APK에서 두 모듈 차단을 재현하고, 수정 빌드에서 해소되는지 확인합니다. 추가로 APK에서 꺼낸 모듈을 수정 없이 연결·실행해 네 화면과 날짜·기록·화면 편집 팝업, 합성 기록 201건·계획·첫 화면 설정·화면 배치의 재실행 보존, 자동 통신 0회를 호스트 대역 환경에서 확인했습니다. 이는 Android WebView를 실제 실행한 검사는 아닙니다.
이 환경에서 Android 실기기·에뮬레이터 또는 실제 브라우저로 화면을 렌더링한 검사는 하지 못했습니다. 암호가 걸린 실제 증명서의 복호화, 최종 화면 배치, 레드커넥트 실기기 실행·복귀와 해당 앱의 예약 과정, 브라우저에서의 APK 다운로드·설치 및 실제 업데이트 후 기록 보존은 기기에서 확인해야 합니다. 실제 기기의 업데이트 설치 완료나 Play 프로텍트 판정은 검증하지 못했습니다.
