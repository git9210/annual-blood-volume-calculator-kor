# 연간채혈량 계산기 2.3.0

헌혈 기록과 직전 1년의 계산량을 기기 안에서 관리하는 Android 앱입니다.
개인이 제작한 비공식 도구이며, 실제 헌혈 가능 여부는 기관의 문진·검사로 결정됩니다.

## 설치

배포용 파일은 `Annual-Blood-Volume-Calculator-2.3.0-Small.apk`입니다.
기존 사용자는 앱을 삭제하지 말고 새 APK를 열어 **업데이트 설치**하세요.
패키지 `kr.bloodnote.app`, 기존 서명, 저장 키, 암호화 방식과 데이터 형식을 유지합니다.
새로 설치한 앱은 기록과 계획이 모두 0건입니다.

- Android 8(API 26) 이상. 증명서 PDF 읽기는 Android 15(API 35) 이상.
- versionName `2.3.0`, versionCode `20`.
- 이번부터 작은 월간 달력만 제공합니다. 기존 Large 설치에도 같은 서명의 이 APK로 업데이트할 수 있습니다.

## 2.3.0 변경 사항: 레드커넥트 실행

- 날짜 팝업의 오늘·미래 날짜에 **레드커넥트 열기** 버튼을 추가했습니다. 완료 기록이 있거나 지난 날짜에는 표시하지 않습니다.
- 달력 아래 장기 계획 목록에서는 **오늘 이후 가장 가까운 계획 한 건**에 같은 버튼을 표시합니다. 계획 삭제·변경·완료 처리 또는 날짜 변경에 맞춰 대상을 다시 계산합니다.
- 버튼을 누를 때만 기기 안에서 레드커넥트를 찾습니다. 실행 가능한 경우 **인터넷·데이터 요금 안내 → 확인 후 실행**을 거칩니다. 취소·뒤로가기·앱을 벗어나기는 동의를 취소하며, 실행할 때마다 다시 확인합니다.
- 설치되지 않았거나 비활성화·기기 정책 등으로 실행할 수 없으면 안내만 표시합니다. 웹사이트·스토어·APK 다운로드로 자동 이동하지 않습니다. 예시 체험에서는 실행하지 않습니다.
- 이 앱은 저장된 헌혈 기록·계획·PDF·계정 정보·파일 접근 권한을 레드커넥트로 전달하지 않습니다. 앱을 여는 것만으로 계획을 저장하거나 예약을 완료하지 않습니다. **선택 완료로 계획을 저장하고, 레드커넥트에서 로그인·장소·날짜·종류·시간을 직접 선택해 예약을 완료**해 주세요.
- 레드커넥트 실행 이후의 인터넷 사용은 해당 앱의 기능·설정에 따릅니다. 계산기의 동의창은 다른 앱의 네트워크를 제한하는 Android 권한 설정이 아닙니다.
- 새 권한·외부 SDK·외부 이미지·폰트는 추가하지 않았습니다. Android의 `<queries>`에 `com.sk.redconnect` 한 항목만 선언하고 기본 실행 Intent를 사용합니다. 전체 앱 목록을 조회하지 않습니다.
- 첨부된 레드커넥트 1.8.41 XAPK의 패키지·실행 선언과 [대한적십자사의 Google Play 등록](https://play.google.com/store/apps/details?id=com.sk.redconnect)을 확인했습니다. 첨부 앱을 설치하거나 그 코드·로고·이미지를 복제·번들하지 않았습니다. 예약 화면을 직접 지정하는 공식 공개 연결 규격은 확인하지 못해 앱의 기본 진입점만 사용합니다.
- 기능 추가에 따라 2.3.0으로 올렸습니다. 기존 패키지·서명·암호화 저장 형식·계산·Small 달력·공휴일 갱신·업데이트 기능을 유지합니다.

## 2.2.1 변경 사항: 마지막 화면과 팝업 닫기

- **설정 → 첫 화면 설정 → 앱 시작 화면 → 마지막 화면**을 추가했습니다. 종료 전에 보던 한눈에 보기·일정 시뮬레이터·헌혈 기록·설정 화면으로 다시 시작합니다. 기존에 고른 고정 시작 화면은 변경하지 않습니다.
- 마지막 화면 설정은 기존 암호화 저장소와 백업에 포함됩니다. 실제 화면 이동 때만 갱신하며, 팝업을 여닫거나 스크롤할 때는 별도로 저장하지 않습니다. 이 기능에는 인터넷을 사용하지 않습니다.
- 저장 전 입력과 열린 팝업은 재실행 시 복원하지 않습니다. 마지막 화면 정보가 없는 이전 백업은 한눈에 보기로 시작합니다. 백업을 복원한 뒤에는 현재 기기에서 실제로 보고 있는 화면을 기억합니다.
- 마지막 화면 모드에서는 뒤로가기로 팝업을 먼저 닫고, 본 화면에서는 두 번 뒤로가기로 종료합니다. 다른 화면으로 강제 이동하지 않습니다.
- **기록 추가·직접 입력·헌혈 날짜 등 팝업의 바깥 영역을 한 번 누르면 닫힙니다.** 저장 전 입력·선택은 반영하지 않고 기존 기록·계획은 유지합니다. 팝업 안쪽 여백을 누르거나, 안쪽에서 바깥쪽으로 손가락을 끌거나, 스크롤이 취소되는 동작으로는 닫지 않습니다.
- PDF 처리·백업 작업 팝업도 바깥을 눌러 닫으면 기존 취소 처리를 거치므로 닫은 뒤에 기록이 등록되거나 백업 작업이 완료 처리되지 않습니다.
- 기존 화면의 사용 방식 보완에 해당하여 패치 버전을 2.2.1로 올렸습니다. Small 달력, 업데이트 확인, 계산, 기존 기록, 서명키와 권한은 그대로입니다.

## 2.2.0 변경 사항: 수동 앱 업데이트

설정 → **앱 업데이트 → 업데이트 확인**을 추가했습니다. 새 메뉴가 추가되어 2.2.0으로 올렸습니다. 달력·계산·기록·화면 표시 설정·공휴일 기능과 암호화 저장 형식은 그대로입니다.

1. 버튼을 누르면 먼저 **데이터 사용, 기기 보안에 따른 설치 제한, 개인 제작 비공식 앱과 이용자의 판단·책임** 안내가 나옵니다. 취소하면 연결하지 않습니다.
2. `안내 확인 · 이번만 연결`을 누르면 아래 저장소의 최신 정식 Release 정보를 한 번 조회합니다.
3. 새 버전이 있을 때 버전과 APK 크기를 보여 줍니다. `다운로드 및 설치`를 눌러야 APK를 받습니다.
4. 파일 크기와 GitHub가 제공하는 SHA-256, APK의 패키지명·서명·버전·최소 Android 버전을 검사합니다. 현재 설치본과 다른 서명, 잘못된 파일 또는 이전 versionCode는 설치를 요청하지 않습니다.
5. 필요한 경우 이 앱의 **알 수 없는 앱 설치** 허용 설정으로 이동할지 묻습니다. 허용 여부는 사용자가 선택합니다. 이후 Android 설치 확인 화면에서 최종 설치를 결정합니다. 무인·강제 설치는 하지 않습니다.

- 앱 시작·종료·화면 전환 시 자동 업데이트 조회나 다운로드를 하지 않습니다. 확인·다운로드 도중 취소하거나 앱을 벗어나면 중단합니다. 중단 후 자동 재시도하지 않습니다.
- 헌혈 기록·계획·PDF·백업은 전송하지 않습니다. GitHub에는 일반적인 접속 정보(IP 등)가 전달됩니다. APK는 앱의 내부 임시 공간으로 받아 설치 프로그램에 그 파일 하나의 읽기 권한만 제공합니다.
- 업데이트에 쓰는 추가 Android 권한은 `REQUEST_INSTALL_PACKAGES`입니다. 기존 `INTERNET` 권한을 함께 사용합니다. 근처 기기·블루투스·위치·공용 저장소 접근 권한을 추가하지 않았습니다.
- 기기의 보안 정책·관리 설정·설치 제한에 따라 완료되지 않을 수 있습니다. 앱은 보안 설정을 임의로 바꾸지 않습니다. 실패했다고 기존 앱을 삭제하지 말고 먼저 암호화 백업을 보관하세요.
- 기존 2.1.1에는 업데이트 기능이 없으므로 **2.2.0 이상 APK를 처음 한 번 직접 업데이트 설치**해야 합니다. 이후 버전부터 이 메뉴를 사용할 수 있습니다.

### 제작자가 GitHub에 새 버전을 올리는 방법

대상 저장소: <https://github.com/git9210/annual-blood-volume-calculator-kor>

1. 같은 패키지와 **기존 서명키**로 빌드하고, AndroidManifest.xml의 versionName 및 versionCode를 올립니다. 앱 화면의 버전 표시도 맞춥니다.
2. GitHub 저장소의 **Releases → Draft a new release**에서 태그를 `v2.3.0`처럼 만듭니다.
3. `Annual-Blood-Volume-Calculator-2.3.0-Small.apk`를 Release의 첨부 파일(Assets)로 올립니다. 파일명과 태그의 버전이 같아야 합니다.
4. **Pre-release로 표시하지 않고**, 최신 정식 Release(Latest)로 게시합니다. 저장소 코드 목록에 APK를 올리기만 해서는 앱이 찾지 못합니다.
5. 다음 배포도 같은 규칙을 적용합니다. 예: 태그 `v2.2.2`, 파일 `Annual-Blood-Volume-Calculator-2.2.2-Small.apk`, versionCode `20` 이상.

앱은 인증 토큰 없이 GitHub 공개 API의 `/repos/git9210/annual-blood-volume-calculator-kor/releases/latest`를 읽습니다. 정식 Release, 정확한 Small APK 이름·주소, 파일 크기와 GitHub의 SHA-256 검증값이 필요합니다. 사전 공개판, 잘못된 이름, 검증값 누락, 32MiB 초과 APK는 설치하지 않습니다. GitHub 조회 제한·통신 실패 시 안내 후 종료합니다. 새 파일은 제작자가 Release에 게시해야 다른 사용자에게 보입니다.

서명키 포함 PRIVATE ZIP은 **절대로 GitHub에 올리지 마세요.** 공개용 GitHub 소스 ZIP과 배포 APK만 사용하세요.

## 2.1.1 변경 사항

- 잔여량 카드의 `90~429mL 구간`처럼 숫자 범위를 반복하던 배지를 제거했습니다.
- 설정 → **화면 표시**에 `잔여량 구간별 표시`와 `헌혈 완료일 강조` 스위치를 추가했습니다. 두 항목은 독립적으로 동작하며 기본값은 켜짐입니다.
- 끈 상태도 재실행 및 암호화 백업 복원 후 유지됩니다. 표시를 바꾸어도 헌혈 기록·계획·계산 기준·계산 결과는 바뀌지 않습니다. 인터넷을 사용하지 않습니다.
- 잔여량 구간별 표시를 끄면 기본 초록 카드로 돌아가고 계산량 충족 설명이 사라집니다. 완료일 강조를 끄면 파란 배경·체크·진한 완료 표시가 사라지며 기존 완료 글자와 날짜 팝업은 유지됩니다.

## 화면 표시와 첫 화면

- 실제 헌혈 기록이 있는 달력 날짜는 파란 배경과 ✓로 표시하고, 해당 종류의 `완료`를 진하게 표시합니다. 날짜가 지났다는 이유만으로 계획을 완료로 표시하지 않습니다. 주말·공휴일의 붉은 날짜와 공휴일명은 유지합니다.
- 잔여량 카드의 배경색과 구간 설명이 함께 바뀝니다. 기본값은 아래와 같으며, 계산 기준에서 종류별 계산량을 바꾸면 구간과 충족 종류도 그 값에 맞춰 바뀝니다.

| 잔여 계산량 | 표시 |
| --- | --- |
| 44mL 이하 | 붉은색 · 최소 계산량 미만 |
| 45~89mL | 갈색 계열 · 혈장 계산량 충족 |
| 90~429mL | 파란색 · 혈장·혈소판·혈소판 혈장 계산량 충족 |
| 430mL 이상 | 초록색 · 네 종류 계산량 충족 |

이 표시는 계산량만 비교합니다. 간격·횟수를 포함한 조건은 다음 헌혈 예상일과 날짜 팝업에서 확인합니다. 입력 기록이 없으면 중립색과 `—`를 표시합니다.

설정 상단의 **첫 화면 설정**에서 한눈에 보기, 일정 시뮬레이터, 헌혈 기록, 마지막 화면 중 선택할 수 있습니다. 선택 즉시 기존 암호화 저장소에 저장되며 백업에도 포함됩니다. 앱을 완전히 종료한 뒤 다시 열면 선택한 화면으로 시작합니다. 실행 중 화면 복원은 보던 화면을 유지합니다. 기존 앱 및 첫 화면 설정이 없는 이전 백업은 한눈에 보기로 시작합니다.

뒤로가기는 팝업을 먼저 닫습니다. 고정 첫 화면을 고른 경우에는 다른 화면에서 그 첫 화면으로 돌아간 뒤 두 번 뒤로가기로 종료합니다. 마지막 화면을 고른 경우에는 현재 본 화면에서 바로 두 번 뒤로가기로 종료합니다. 로고를 누르면 계속 한눈에 보기로 이동합니다.

## 날짜 팝업

1. 7열의 작은 월간 달력에서 날짜를 누릅니다. 주간·월간 전환은 제거했습니다.
2. 팝업에 날짜·요일·공휴일명과 네 종류가 나옵니다. 위에는 전혈/혈장, 아래에는 혈소판/혈소판 혈장이 배치됩니다.
3. 종류를 누르면 예상 잔여량과 제한 이유를 보여 줍니다. `선택 완료`를 눌러야 계획에 저장됩니다.
4. 저장된 날짜를 다시 누르면 기존 종류가 선택됩니다. 다른 종류로 변경하거나 `계획 취소`를 누를 수 있습니다.
5. 예정일이 오늘이거나 지나면 실제 헌혈 여부에 따라 기록으로 남기거나 계획을 취소합니다. 자동으로 완료 처리하지 않습니다.

계산 조건을 충족하지 않는 가정도 시뮬레이터에서 검토할 수 있습니다. 이 경우 붉은 제한 표시와 이유를 확인한 뒤 `제한 있는 가정으로 저장`을 명시적으로 눌러야 합니다. 실제 예약 기능이 아닙니다.

잔여량 기준일은 한국 시간의 오늘로 고정합니다. 상하단 월 이동, 기록 5건 단위 표시, PDF 검토, 백업, 암호화 저장과 수동 공휴일 갱신을 유지합니다.

## 오프라인·개인정보

화면, 계산, 계획, PDF 분석과 암호화는 기기에서 처리합니다. 공휴일은 사용자가 🔃를 누르고 이번 갱신의 인터넷 사용을 허용했을 때만 가져옵니다. 앱 업데이트도 설정의 버튼을 누르고 매번 안내에 동의한 경우에만 GitHub에 연결합니다. 앱에 광고·분석 SDK는 없습니다.
외부 출처 링크를 누르면 브라우저가 열립니다. 이전 개인용 웹앱 링크는 배포본에서 제거했습니다.

앱 저장 데이터는 Android Keystore 기반 AES-GCM으로 보호합니다. 내보내는 백업은 사용자 비밀번호에서 키를 만든 AES-GCM 암호문입니다. 원본 PDF는 앱에 복사하거나 배포하지 않습니다. 앱 삭제나 데이터 삭제 전에 백업하세요.

## 소스와 빌드

앱 실행에 별도 JavaScript 라이브러리, CSS 프레임워크, Gradle 플러그인은 사용하지 않습니다.

- `assets/`: HTML/CSS/JavaScript, 계산 엔진, 로컬 공휴일 자료·라이선스
- `src/kr/bloodnote/app/`: Android WebView, 보안 저장, PDF 읽기·분석, 수동 업데이트·APK 읽기 전용 제공·레드커넥트 실행
- `res/`: Android 리소스와 직접 작성한 벡터 아이콘
- `tools/generate_icons.py`: 외부 이미지 없이 도형 좌표에서 아이콘 재생성
- `tests/`: 합성 데이터로 동작을 검사하는 개발용 코드

빌드 환경: JDK 17 이상, Python 3, Android SDK platform 36 및 build-tools 36.0.0.
SDK 위치를 `ANDROID_HOME`으로 설정하고 프로젝트 폴더에서 실행합니다.

```sh
python3 tools/generate_icons.py
node --test tests/*.test.mjs
node tests/android-shell-smoke.mjs
python3 tests/run-java-tests.py
python3 tests/run-red-connect-tests.py
python3 build.py
```

`build.py`는 표준 SDK 설치 경로와 기존 작업 환경의 SDK 경로를 지원합니다.
별도의 Python/Node 패키지 설치 없이 기본 빌드·JS 검사가 가능합니다.
선택 사항인 실제 PDF 비교 검사만 PC에 `pypdfium2`와 `pdftotext`가 필요합니다. 해당 도구는 APK/ZIP에 포함하지 않습니다.

PRIVATE 원본은 기존 `signing/release.jks`와 `signing/password.txt`로 빌드합니다.
GitHub 소스만 빌드하면 **새 서명키가 로컬에 생성**됩니다. 새 키로 만든 APK는 기존 배포 APK 위에 업데이트 설치할 수 없습니다. 기존 사용자에게 업데이트를 배포할 제작자는 원래 키를 공개 저장소 밖에서 보관하고 사용해야 합니다.
향후 업데이트는 versionCode를 올리고 같은 패키지·서명·로컬 화면 출처를 유지하세요.
